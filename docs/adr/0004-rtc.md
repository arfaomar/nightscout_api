# Real-Time Communication: Node.js Socket.IO Bridge

## Status
`Accepted`

## Context
During development, we discovered that AndroidAPS relies on Socket.IO for real-time communication (RTC) with Nightscout. Our project was originally designed around a pure REST API, which is not compatible with the RTC needs of AndroidAPS. We attempted to implement Socket.IO support directly in PHP using the [walkor/workerman](https://github.com/walkor/workerman) library, which matches the Socket.IO version used by Nightscout. However, we encountered significant issues and were unable to achieve stable or reliable communication.  
Switching the backend to Node.js was not an option, as the project requires PHP and our hosting provider (Hetzner) only supports PHP applications.

## Decision
After consulting with our professor, we decided to implement a [**Node.js-based bridge**](https://code.fbi.h-da.de/pse_nightscout/aaps-laravel-bridge). This bridge handles Socket.IO connections from AndroidAPS, intercepts the real-time communication, and relays messages to our REST API. This approach allows us to meet the real-time requirements of AndroidAPS without re-architecting the PHP backend. We have successfully built a minimal prototype that fulfills the project requirements.

## Consequences
- Real-time communication with AndroidAPS is now possible by bridging Socket.IO and our REST API.
- The bridge cannot be hosted on Hetzner due to hosting limitations, so **each AndroidAPS client must run the bridge locally** in their environment.
- Adds complexity, as the bridge introduces an additional Node.js service that each client must install and manage.
- Maintenance and deployment require both PHP and Node.js environments.
- This solution allows us to satisfy project requirements without a backend rewrite or changing technology stacks.

## Alternatives Considered
- **Pure PHP Socket.IO implementation:** Tried using the walkor/workerman library, but it did not provide reliable Socket.IO support in our context.
- **Rewriting the backend in Node.js:** Not possible, since the project requires PHP and Hetzner only allows PHP applications.
- **Dropping real-time support:** Not an option, since RTC is essential for AndroidAPS compatibility.
