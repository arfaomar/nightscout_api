# Database Technology Choice

## Status
`Accepted`
*Supersedes [ADR-0003: Database Technology Choice](./0003-db.md)*

## Context
Our initial decision was to use MySQL as the database for our project, mainly because it was the default in Laravel Sail and provided quick setup. However, as deployment neared, we discovered that our hosting provider (Hetzner) only supports **MariaDB** and **PostgreSQL**—not MySQL. While MariaDB claims compatibility with MySQL, we did not want to risk subtle incompatibilities or migration issues. Additionally, our team has more experience with PostgreSQL, which made it a more comfortable and reliable choice.

## Decision
We decided to switch our database from **MySQL to PostgreSQL** to ensure compatibility with Hetzner’s hosting environment and to leverage our team’s familiarity with PostgreSQL.

## Consequences

- Database setup and migrations needed to be adapted from MySQL to PostgreSQL.
- **Fortunately, we had not started development with MySQL yet, so the switch was easy and did not require any data migration.**
- We avoid possible compatibility issues that might arise from using MariaDB as a MySQL drop-in replacement.
- The team can work more confidently and efficiently with a database system we know well.
- Some SQL syntax or ORM behaviors might differ between MySQL and PostgreSQL, requiring minor code adjustments.

## Alternatives Considered

- **Continue with MariaDB:** Possible, since it’s compatible with MySQL, but we did not want to risk running into edge cases or compatibility bugs.
- **Stay with MySQL:** Not possible, as Hetzner does not directly support it.
- **Other databases:** Not considered, since PostgreSQL is fully supported and meets all our requirements.
